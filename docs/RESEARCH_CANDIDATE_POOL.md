# 可測試的研究方向池

更新：**2026-10-06（Asia/Taipei）**。依使用者最新要求，此階段繼續累積有實際用途、能提出辨別實驗的方向，之後再整合測試。本文沒有選定勝出主題，也沒有執行新 probe、修改 app 或開始採集。

原本的建築物、樓層、區域離開、進入／重訪、共同移動等問題，保留在 [APPLICATION_RESEARCH_DIRECTIONS.md](APPLICATION_RESEARCH_DIRECTIONS.md)。以下擴充與細化其他能力；「可測」表示有可檢查的機制與對照，不表示已證實有效或具有新穎性。

使用者方向與上一輪候選的 **8 項簡介、成功情境模擬及相關研究**，整合於 [RESEARCH_DIRECTIONS_SUMMARY.md](RESEARCH_DIRECTIONS_SUMMARY.md)（2026-10-07 原文重驗）。依使用者要求，原簡表第 9～11 項（本文 T07～T09）已排除，不列入後續候選；本文相關段落僅保留歷史紀錄。

## 共同前提

- 主叫端每次 probe 至多取得一筆結構化 cell 資訊。可以利用多次 probe 的歷史，但不能把它說成同時讀取多個鄰居 cell。
- 主叫端可用輸入包括實際收到的 CNI、封包時間、完整且配對的回應流程、可見性與其他實際出現的欄位。目標端位置、速度、RSSI、neighbor cells 與人工事件只作調查、真值與控制。
- 已知場域地圖與事前調查可以作應用條件；未調查地點的推論須另行驗證。塔座標、理想圓形範圍與 ECI 前綴都不等於已測量的覆蓋區。
- 目標失去普通 Wi-Fi 後，現有 Cell ID 管道可能中斷。缺資料是 unknown，不能直接標成離開、停止或忙線。移動熱點會改變應用條件。
- 依使用者於 2026-10-07 確認的方法條件，以「成功取得的 CNI cell 為當次最新值」評估，不將未驗證的 CNI 過時可能性當成已知限制。採樣間隔仍可能漏掉切換；目標 radio snapshot 的快取與跨手機時鐘誤差只作真值對照的問題，不能據此推定 CNI 過時。
- 過去 Wi-Fi／hotspot 的 timing 與路徑特徵差異未重現。本文不把它們重新宣稱為可用指紋，也不默認 PANI、History-Info、Reason 等欄位存在。

## 一、位置與移動能力：新增／細化七個問題

### T01：單筆 ID 一樣，多筆分布能否分辨位置？

**問題：** 兩個地方的第一筆都是 cell A，後續短時間的 ID 比例、持續時間、回跳模式，能否讓主叫端分辨它們？

**用途：** 辨認商場不同區域或鄰近建築物；改善單筆 Cell ID 的空間歧義，不必要求每個區域有專屬 cell。

**可能機制：** 位置甲經常出現 A/B，位置乙經常出現 A/C；這些是待測的時間分布例子。若位置影響 cell 選擇且 caller reporting 保留差異，短歷史可能形成經校準的空間指紋。沒有 RSSI 的分布指紋仍需獨立證據。

**辨別情境：** 共用第一筆 ID 的兩個以上固定位置，多次完整停留、不同日期與時段。比較單筆、相同查詢預算的短歷史和時間基線；不要把相鄰樣本隨機拆到訓練與測試。

**何時不成立：** 差異只跟時段、網路負載或先前旅程有關；新日期沒有差異；增加 probe 仍只觀察到同一個目前 cell，沒有額外區辨資訊。這不是三角定位。**現有設備可測，成立程度取決於場域。**

### T02：Cell 切換能否成為定位地標？

**問題：** 在已知走廊／路徑上，剛從 A 切到 B，是否能把位置限縮到比整個 B 覆蓋區小得多的一段？

**用途：** 在公里尺度的粗估之內，辨認經過入口、通道或接近服務點的區段。

**可能機制：** 多次走同一路徑時，某個轉換可能集中在較短位置區間。Cell ID 序列與校準切換位置有直接前例，但手機端觀察和 caller CNI 不同。[CAPS，MobiSys 2011 原文](https://cseweb.ucsd.edu/~schulman/class/cse291_w17/docs/paek_caps.pdf)

**辨別情境：** 同路徑雙向通行、不同速度、不同日，加入切換區的原地停留。分別量實際 cell 更新位置與 caller 回報位置，不把遲報當成物理邊界。

**何時不成立：** 切換位置散布太廣、方向／速度依賴太強、原地也常切換，或回報延遲使範圍反而變大。**已知路徑與普通 Wi-Fi 可觀察區內可測。**

### T03：地圖、上一個可靠位置與現在的 cell，能否共同縮小候選區域？

**問題：** 同一個 cell 涵蓋多個區域時，能否利用最近的可信位置、經過時間與可通行動線，排除部分現在不合理的位置？

**用途：** 把服務／搜尋範圍限縮到某一館、可到達的連通區域或幾條路，而非直接給過度精確座標。

**可能機制：** 保留多個可行路徑，結合經驗覆蓋範圍與地圖限制。空間／時間先驗有幫助，但必須驗證 caller 資訊對「只有地圖＋時間」是否真的增加能力。相關 cellular 路徑研究使用更豐富的覆蓋資料。[Cell*，CoNEXT 2014](https://conferences.sigcomm.org/co-next/2014/CoNEXT_papers/p121.pdf)

**辨別情境：** 最新 ID 一樣、先前路徑不同的分岔；有／沒有可信起點；可選電梯、樓梯、替代入口的情境。評分同時包含候選面積／區域數量與真實位置保留率。

**何時不成立：** 模型只是把人吸到常走路線；錯誤行走速度或覆蓋假設排除了真值；縮小結果沒有勝過地圖基線。**需可信起點、地圖與校準範圍；既有手機可收集驗證資料。**

### T04：能否辨認開始移動、停止，以及粗略移動狀態？

**問題：** 即使仍在同一棟建築物，能否分辨長時間停留與持續跨區域移動，並標出 stop/resume 事件？

**用途：** 調整 probe 間隔、在開始移動時重新確認位置，或在停留時提供適合閱讀的資訊。這些是應用決策，不能直接當成注意力／人類活動辨識。

**可能機制：** 不同 ID 數量、每個 ID 的持續時間、重複與回跳模式。Mun 等研究的 GSM-only 分支使用單一 connected cell ID 與時間特徵，提供正面支點；整體模型另有 Wi-Fi，採樣與 caller CNI 不同，不能轉移成功率。[作者上傳原始研究，HotEmNets 2008](https://www.researchgate.net/publication/228523926_Parsimonious_mobility_classification_using_GSM_and_WiFi_traces)

**辨別情境：** 原地且 cell 切換、同 cell 內走動、走動後停下再出發；同區域不同步速、不同 cell 密度地點，以及靜止 Wi-Fi 中斷。把未改變 CNI 的真實移動留在分母。

**何時不成立：** 原地與移動歷史重疊，或規則只是「ID 改變」。**普通場域 Wi-Fi 內的停留／步行可測；車輛與特定交通工具分類暫列條件延伸。** 不能用切換次數直接換算速度；塔與塔距離也不是人的移動距離。

### T05：能否知道路線、方向、回頭或偏離？

**問題：** 同樣的目前 cell，前後順序能否分辨正向／反向、分岔路線或中途回頭？

**用途：** 辨認朝服務點前進、遠離，或偏離預期路線；支援接送、已知場域導引與授權設備的路徑檢查。

**可能機制：** 校準路徑可能有不同 ID 順序；先前觀察可解除最新 ID 的歧義。序列本身也可能相同，需容許多個路線／unknown。路線辨識已有 Cell-ID handoff pattern 研究。[原始研究出版頁，2015；本次摘要可得](https://www.sciencedirect.com/science/article/abs/pii/S0950705115002464)

**辨別情境：** 雙向路徑、共用起點後分岔、折返、繞路與停留；整趟旅程／不同日留出。比較 latest-ID、時間與起點先驗，避免只辨認固定實驗順序。即時方向／偏離判斷只用決策當下已有的歷史；後續觀察另作回顧路徑評分。

**何時不成立：** 所有路線都有相同序列；普通 Wi-Fi 缺口覆蓋了關鍵分岔；辨認結果只由起點／時間決定。**已知場域路徑可測；一般戶外連續追蹤不由此成立。** 恢復連線後回顧中途路徑，是此問題的另一評分端點，不能當成即時資訊。

### T06：能否提前預測下一區域或近期到達？

**問題：** 在尚未到達時，caller 歷史能否提高「接下來進入哪一區」或「在指定時間內到達」的預測品質？

**用途：** 提前準備接送／服務、預載下一區資訊。輸出是機率或時間區間；到達證據另行處理。

**可能機制：** 在有可辨識路線進度的場域，序列、停留時間及方向可能補充移動先驗。這是推論假說，沒有文獻證明當前 CNI 能力。AI 可以學序列與機率，但例行路線或時間本身可能提供大部分預測。

**辨別情境：** 同起點／同時段不同目的地、延後到達、停下、回頭與繞路。只用預測當下已有的資料；與時間／例行習慣／起點基線比較，量錯誤提前通知與機率校準。

**何時不成立：** 加入 CNI 不比簡單先驗好，或借用了未來資料；觀察缺口中的猜測被當成已到達。**可與 T05 共用資料，適用性依普通網路可觀察路段而定。**

### T07：少量後續 probe，能否換到更新、更可靠的資訊？

**問題：** 長時間未查詢後，第一筆可能是舊資訊；在原有間隔限制內追加少量查詢，是否更可能取得反映現在位置的資料？

**用途：** 按需定位時，決定一筆是否足夠，或值得付出有限追加成本。研究量是有效新資訊，不是增加追蹤頻率本身。

**可能機制：** 第一筆與後續筆可能有不同更新情況；probe 也可能影響被叫端／網路狀態。這是尚無正面證據的因果假說，時間自然經過是主要競爭解釋。

**辨別情境：** 安靜後第一筆與後續筆，對照「相同總等待時間後才做第一筆」，條件順序隨機或交錯安排。另外比較固定位置與真實 cell 轉換，控制 logger、螢幕與 caller 重啟；辨認新鮮的 modem 測量，使用真實 CNI 回應時間。

**何時不成立：** 相同等待後首筆同樣新鮮；重複 probe 只讀同一快取或造成干擾；更多資訊完全來自目標 logger 的喚醒。**現有設備可測，但信心低於空間拓樸型假說。** 不預設提高現行頻率、不預設節電，也不把結果當成螢幕使用辨識。

## 二、非位置資訊：另外兩個條件方向

### T08：轉接後，Cell ID 到底屬於哪個對象？

**問題：** 撥給甲但轉接到乙時，caller CNI 描述甲、乙、舊資訊，還是沒有可歸屬來源？主叫端能否知道何時歸屬不可靠？

**用途：** 避免把另一端點的位置套在原目標身上；改善定位身份與資料來源判斷，同時測試轉接狀態是否透露。

**可能機制：** 181、History-Info、回應分支與 CNI 可能在轉接時改變；標準有轉接通知與隱私條件，實際網路可能抑制它們。[TS 24.604 V18.0.0，2024-05](https://www.etsi.org/deliver/etsi_ts/124600_124699/124604/18.00.00_60/ts_124604v180000p.pdf)

**辨別情境：** 直接呼叫／無條件轉接／關閉轉接；甲乙在不同、已驗證的 cellular context，再交換位置或網路條件。目標與轉接端資料作真值，generic Contact／SDP 變化不作身份證明。

**何時不成立：** caller 欄位不能辨認來源，或訊息被網路隱藏／重寫；no-answer 轉接尚未發生就被我們 CANCEL。**可靠的甲乙來源控制需要另一個授權端點／號碼，不屬已確認設備。** 不預設延長未接聽探測或更動轉接設定。

### T09：定位管道不可用時，是否仍可聯絡／辨認粗略通話狀態？

**問題：** 無 CNI 是否只是沒有定位資訊？能否分辨仍有語音服務、暫不可聯絡，或部分建立通話／來電等待狀態？

**用途：** 選擇稍後重試或適合回撥的時機；避免把無定位資訊解讀成設備離開或關機。

**可能機制：** 配對 INVITE 的完整回應種類、階段與時間。Ghost Calls 已有初始 SIP 的通話建立狀態研究，但閒置／通話中、VoWiFi-ready／VoLTE-ready 未被各自分開。[原始研究，MobiCom 2020 §5.1](https://xietian1.github.io/paper/Mobicom2020.pdf)

來電等待另有標準定義的 Alert-Info 語意；較晚 180 才出現的訊號可能被目前 first-183 CANCEL 截斷，而且可能引發響鈴，須列為不同觀察條件。[RFC 7462，2015](https://www.rfc-editor.org/rfc/rfc7462.html)，[TS 24.615 V16.0.0，2020-11，非最新版宣稱](https://www.etsi.org/deliver/etsi_ts/124600_124699/124615/16.00.00_60/ts_124615v160000p.pdf)

**辨別情境：** 保持位置不變，對照 Wi-Fi Calling 可用／關閉但 cellular voice 可用／所有 voice access 不可用；另外的通話建立、通話中、DND 與來電等待對照需授權背景端點。真實可聯絡性用獨立正常呼叫及原目標手機實際收到來電／建立通話驗證，不用 183、語音信箱、網路公告或轉接端的回應定義真值。

**何時不成立：** 相同回應涵蓋多種狀態；只有在延長至響鈴／接聽後才可見；分類只是網路路徑噪音。487 若來自我們的 CANCEL，不能當狀態訊號。**先看現有取消點前的資訊，較晚訊號與背景呼叫另有資源／流程條件。** 忙線也不能直接解讀成對方正在講電話。

## 三、應用能否擴展：兩個支援問題

這兩項改善部署／可靠性，不算新的封包資訊種類。

| 問題 | 實際價值 | 後續辨別條件 |
|---|---|---|
| 一次場域調查能否支援其他人／手機？ | 百貨公司調查一次，不必替每個使用者完整重做 | 不同 target handset 的整趟拜訪留出；同電信商先測，必要時交換 SIM；需要額外目標手機。既有跨裝置研究使用 multi-cell RSS，不能套用其方法。[OmniCells，PerCom 2020 原文](https://staff.itee.uq.edu.au/jaga/proceedings/percom2020/papers/p79-rizk.pdf) |
| 何時應讓舊建築物／樓層判斷失效？ | 減少錯誤位置持續展示的時間 | 比較固定到期時間與 caller 證據的有效性規則；同時量錯誤保留時間與 unknown 覆蓋，不能用 age=0 保證即時。單純加入 timeout 是政策，還不是新推論。 |

## 四、之後哪些資料可以共用？

這是資料需求分組，尚未指定採集日程、樣本數、設定或執行順序。

| 未來資料類型 | 可以共同檢查的問題 | 不能漏掉的對照 |
|---|---|---|
| 多個固定位置的完整停留 | 建築物／樓層、T01、T04、資訊有效性 | 同 cell 不同位置、原地 cell 切換、不同日／時段 |
| 雙向、分岔、折返的場域行走 | T02–T06、入口／離開／返回 | 同最新 ID 不同歷史、同 cell 內移動、未見過水平位置、真正缺資料的路段 |
| 停下、等待、重新出發 | T04、T06、probe 排程 | 原地 cell 變化、短暫離開再返回 |
| 安靜時間與追加查詢條件 | T07、新鮮程度 | 相同等待但沒有前次 probe；logger／螢幕／重啟控制 |
| 靜止下的 voice access／通話／轉接條件 | T08–T09、Wi-Fi loss 語意 | 無 CNI 但可正常聯絡、DND／拒接、自己的 CANCEL、多端點來源 |
| 不同裝置的重複場域拜訪 | 跨裝置部署、共同移動條件延伸 | 整個 target device 留出，不能用同手機的日期切分取代 |

同一份資料可以回答多個問題，但每個問題有自己的預測目標、對照與失敗條件。一個結果成功，不等於其他能力一起成立。先保存完整事件與 ordinary access 的未知區間，之後才能公平比較哪些方向留下來。

## 五、研究與審查紀錄

此輪由空間／應用、非位置狀態、獨立候選審查三個分工並行。採納的主要修正：移動狀態有 ID-only 早期支點，但不轉移成功率；地圖結果必須勝過地圖／時間先驗；未來預測禁止未來觀察洩漏；短追加 probe 須有相同等待對照；轉接／通話狀態必須標記額外端點與較晚觀察需求；transfer 與 expiry 明確列為支援能力。

其他查讀／反例：

- [CTrack，NSDI 2011 作者原文](https://people.csail.mit.edu/lenin/papers/CTrack-Paper-NSDI11.pdf)：cellular 地圖匹配使用多 cell RSS，另有可選 motion/turn 感測提示；不能把其軌跡準確度或能耗當成 caller CNI 的成果。
