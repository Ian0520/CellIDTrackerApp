# 百貨公司 Cell 資料庫與定位精度：目前主線

更新：**2026-10-28（Asia/Taipei）**，依使用者決定調整研究優先順序。

**主線：本機建立已知場域資料庫，離線研究定位改善，再用 caller probe 驗證。**

優先研究建築物／區域、樓層與 Cell 切換定位地標。**離開偵測與減少 probe 改為備案**；目前不要求進出 episode、原地 Wi-Fi 開關或全日持續 probe。先前完整流程留在 [四方向設計](FOUR_DIRECTION_EXPERIMENT_PLAN.md) 與 [舊現場手冊](MALL_FIELD_EXPERIMENT_RUNBOOK.md) 作方法參考，本文件為目前執行依據。

## 1. 研究問題與成功假設

問題：在已建立資料庫的百貨公司內，**單一完整 Cell 身分與其時間歷史，是否能比同一資料庫的單筆查表，提供更精確的位置資訊？**

| 方向 | 想像中的成功結果，尚待驗證 |
|---|---|
| 建築物／區域 | 多處都能看到 A，但短時間內 A/B/C 的分布不同，能把候選位置縮到受測區域。 |
| 樓層 | 不同樓層共用 A，加入其他 ID 的出現比例或順序後，仍能區分樓層。 |
| 切換定位地標 | 單看 B 可能位於多處，先 A 後 B 的觀察序列集中於特定路段，能縮小候選範圍。 |

第一個目標是區域、樓層或路段的可辨識性。只有在具備可靠圖面尺度／位置真值時，才計算公尺誤差。已知場域建庫成果不代表未調查過的建築物也能直接使用。

## 2. 三階段流程

| 階段 | 採集與工作 | 階段要回答的問題 |
|---|---|---|
| A 本機建庫 | 用 LocationData，記固定點、不同樓層、雙向內部路線及原地控制；以 session 標籤與少量 checkpoint 提供真值。 | 本機 Cell 模式是否包含可重複的位置差異？ |
| B 離線定位分析 | 比較單筆查表、短時間集合／比例、短序列與動線模型；依預期探測間隔抽樣，於獨立資料評分。 | 相近等待時間、可輸出比例下，是否提高區域／樓層正確率或縮小候選範圍？ |
| C Probe 驗證 | 選有成果的代表點與路線，同步錄本機與 caller；凍結方法後測實際 CNI 輸入。 | 本機學到的資訊能否經探測管道取得，改善是否保留？ |

第一輪小範圍建庫可以完全不 probe。**本機初步有差異後、擴大建庫前，先做少量配對確認**，檢查本機選取的 Cell 與 caller CNI 的對應；後續再做獨立日期的正式 probe 驗證。這項橋接不要求把全部本機採集改成同步探測。

## 3. 本機先收什麼

### 固定點與樓層

- 沿用同一棟樓的不同樓層，每層包含不同水平位置；跨層點盡量水平對齊。
- 以少量建築外／鄰近其他場所作負例；外部資料可用性和受測範圍另列。
- 每個固定點單獨建立 LocationData session，condition 寫點位代碼。到點 Start，原地停留，仍在該點時 Stop & export；整段共用位置／樓層，不逐筆標記。
- 至少保留一個較長原地段，檢查原地的 ID 分布與切換。

### 室內路線

- 沿一條已知內部路線往返，涵蓋同樓走動與上下樓；改變方向／正常步速，保留少量替代路徑或折返。
- 起終點為已知位置；路線中間及上下樓兩端用少量事件錨點。兩錨點之間保留路段／換樓區間，不用均速插值或高度取整數製造精確真值。
- 先小範圍試錄，檢查實際更新與差異；不必先完成舊手冊的全部趟次或進出數量。

## 4. 資料庫保存與主模型輸入

| 資料 | 用途 |
|---|---|
| 場域、實際樓層、區域、點位、路線、方向、日期／到訪、session 對照 | 位置標籤、切分資料與重現實驗 |
| 原始 Cell tuple：RAT、MCC、MNC、area、cell ID；registered 狀態 | 從明確已註冊資料中建立單一 Cell 輸入；不只使用 CID 數字 |
| 記錄時間、radio 量測時間／age、實際取樣間隔及缺口 | 品質檢查與模擬稀疏觀察 |
| 少量人工事件與點位／樓層對照表 | 固定點與路線真值 |
| 鄰區、訊號、Timing Advance、Wi-Fi、位置／高度／速度、電源 | 保存原始診斷資料；主模型輸入仍限單一 Cell 與時間歷史 |

若另外分析多 cell、RSSI、Wi-Fi 或高度的效果，清楚列為 local-only／target-assisted 比較，不算 caller-only 成果。位置／樓層真值也不作為未知位置模式的隱藏輸入；已知起點追蹤另列。

### 現有 LocationData 的品質檢查

- `servingCell` 欄位在沒有 registered cell 時會退回第一個 cell，離線必須明確檢查 `servingCellIsRegistered=true`。同時有多個 registered／不同 SIM 或 RAT 時，保留歧義，依事前固定的選取規則處理，不能挑最能定位的那筆。
- 用原始 observed cell；`stableCell`／confirmed transition 已含多樣本去抖，不作每筆原始 Cell 的替代。
- 目前 radio 收集隨 location callback 執行，室內位置更新停住時，radio 記錄也可能停止；先試錄並檢查真實 cadence。
- Android 本機讀值可能是快取，保留量測 age，重複 callback 不算新的 radio 量測。這是本機採集品質問題；caller 成功收到 CNI 最新的前提沿用。

程式依據：LocationData 的 `GroundTruthViewModel.kt:onLocation` 與 `TelemetrySnapshot.kt:captureRadio`；API 行為見 [Android TelephonyManager](https://developer.android.com/reference/android/telephony/TelephonyManager#getAllCellInfo())。

## 5. 離線分析比較

1. **同資料庫的單筆查表**作基本基準：目前 ID 對應哪些區域／樓層，允許候選集合與未知。
2. 比較短時間 ID 集合、比例、連續觀察時間；再加有方向的短序列。
3. 有動線模型時，另與「只有動線、時間／已知起點」比較，檢查 ID 額外提供多少資訊。
4. 依預期 probe 間隔，例如 10／30／60 秒，模擬每次只取得一個當時已可取得的 Cell；重跑不同起始相位。缺值保留，不用未來最近樣本補齊，不把密集本機分析冒充實際 probe 結果。
5. 一個日期／完整到訪用於建庫調整，另一天凍結測試；另留同一建庫區域內、未參與建庫的水平測點或不同抵達路徑。未採點與未建過的新類別／新建築分開報告。

### 評分

- 區域／樓層混淆與正確率，包含外部負例及未知。
- 候選區域大小／路段長度，以及保留真實位置的比例；避免靠錯刪真值縮小範圍。
- 可輸出比例、未知比例、開始需要觀察多久；相同等待／可用性條件下比較。
- 原地誤觸發地標與替代路徑混淆。
- 冷啟動、已知起點追蹤分開；不隨機拆相鄰樣本增加表面分數。

## 6. Probe 驗證

先挑少量代表固定點與一條已知路線，同步記錄 LocationData 與 caller。核對兩端 Cell 對應、時間差與實際 probe 節奏；不因 CNI 最新就預設 Android API 同時一定回傳相同 Cell。

方法凍結後，用另一日期的 CNI 流直接評估，保留沒 CNI、未見過 ID、重啟與記錄缺口的分類。若必須重新訓練／調整對應，使用獨立校準資料，再另留測試資料。

本機在無 Wi-Fi 的外部仍可能記到 Cell；該段在 caller 可能不可觀察。因此分別報本機定位能力與探測端可用性，不把本機全程可見當作遠端效果。

## 7. 備案與目前下一步

**備案保留：** 實體離開偵測、原地 Wi-Fi-off 與出門對照、SIP 延遲／回應流程分類、固定與動態省 probe。舊手冊的進出 episode 與排程實驗不再是本輪必要採集。

**下一步：** 先完成一個已知場域的小範圍本機資料庫，輸出各點／樓層的 Cell 分布、路線序列與資料品質摘要，再決定擴充位置及最有希望的定位方法。本文件調整研究與採集順序，尚未啟動實驗或新增 App 功能。
