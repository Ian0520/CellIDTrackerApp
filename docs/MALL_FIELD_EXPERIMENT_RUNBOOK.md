# 百貨公司四方向實驗：完整現場操作手冊

版本：2026-10-27。依目前兩個專案的實際操作介面核對；尚未執行新採集或修改 App。

**2026-10-28 範圍更新：** 目前主線改為 [本機建立資料庫、離線提升定位精度、再以 probe 驗證](LOCAL_DATABASE_PRECISION_PLAN.md)。本手冊保留為先前四方向的完整操作參考；§8 進出偵測與 §11 省 probe 改為備案，原先全日 caller 與 52 段採集數量不再是本輪要求。第一輪可只用 LocationData，沿用固定點／樓層、原地控制與內部路線的標記方法。

目的：用同一批資料檢查 **建築物／區域辨識、樓層辨識、Cell 切換定位地標、離開偵測與減少 probe**。方法與文獻見 [四方向實驗設計](FOUR_DIRECTION_EXPERIMENT_PLAN.md)、[文獻審查](FOUR_DIRECTION_LITERATURE_REVIEW.md)。本手冊補上現場順序、按鈕、數量與資料交付。

## 0. 先看整體安排

| 階段 | 要做的事 | 估計時間／產出 |
|---|---|---|
| 出發前 | 確認兩機版本、記錄與匯出可用，準備點位表 | 約 20–30 分鐘；首次處理環境問題另計 |
| Day 0：場勘 | 六點、原地控制、少量水平／上下樓／出入對照 | 現場約 60–90 分鐘；決定值得正式測的地方 |
| 場勘後 | 檢查實際檔案，凍結點位、路線與正式流程 | 在電腦完成，不必當天在百貨公司分析 |
| Day 1：正式採集 | 固定點、八趟路線、十二個進出／對照 episode | 約 3–4 小時，依人流、距離與操作熟悉度而變 |
| Day 1 後 | 開發／調整方法，凍結測試規則 | 此時仍不能看 Day 2 結果來挑方法 |
| Day 2：另一日期 | 重做相同組合，改變順序與部分抵達路徑 | 約 3–4 小時；獨立日期初測 |
| 分析後 | 先重播比較少 probe；有收益才做實際頻率／動態排程複測 | 另排日期；目前不必先實作動態排程 |

兩個正式日期的核心量：**12 段固定點停留、16 趟主路線、24 個進出／對照 episode**。其中兩點每天各延長到 10 分鐘，兼作原地控制，不另增加一次採集。這是小規模可行性初篩，並非足以證明產品可靠度的樣本數。

### 本手冊固定的條件

- 研究者自有／已授權的目標手機；主叫端固定，目標端隨人移動。
- 收到的 Cell ID 視為該次最新值；一個成功 probe 至多一個 ID，允許使用歷史。
- 場域原有普通 Wi-Fi；不帶隨身熱點補覆蓋，不架設備，不錄音、錄影。
- 主叫端本輪選 **10 秒**設定。它是本實驗的固定選擇，**不是目前程式的硬性下限**；實際發送可能較晚。
- 主叫端模型只用允許的 caller 觀測。目標端高度、Wi-Fi、訊號與人工標記只供真值／校準，不能混入 caller 推論。
- 沒有 CNI 是未知，不能直接當成離開；Wi-Fi 覆蓋邊界不等於實體門線。
- 本輪沒有自動樓層、氣壓記錄、預設標記快捷鍵或即時離開通知；目前能先採資料，之後離線分析。

## 1. 出發前：準備一次就好

### 1.1 設備與分工

1. 主叫手機：現有可正常工作的 CellIDTracker、原本的 root／網路環境，留在固定位置；不必跟著目標走。
2. 目標手機：現有 LocationData（畫面標題 `Ground Truth Recorder`），帶進場域，使用原本 SIM 與 Wi-Fi Calling 設定。
3. 充足電量，必要時使用相同供電方式；事先確認可用儲存空間。每輪保持持法、朝向習慣、手機位置與螢幕政策一致。
4. 一份紙本或離線文字清單，記點位、順序、開始時間與異常。可用手機時鐘／手錶計時；現有 App 沒有本手冊所需的自動倒數標記。
5. 一人也能做：先啟動固定位置的主叫端，帶目標端走流程，回來後停止主叫端。有協助者時可由其檢查主叫端是否仍運作，不要求增加現場觀察員。

### 1.2 在熟悉位置做一次 2 分鐘試錄／試匯出

1. 核對安裝版有本手冊列出的按鈕；記兩 App 版本、兩機機型、系統、業者與 SIM 設定。若安裝版不同，先解決版本差異再採正式資料。
2. 兩機開啟自動日期／時間。使用同一參考時鐘檢查並記錄可見鐘差與檢查方式；若只能確認到數秒，後續時間結果保留這個不確定範圍。不直接比較兩機各自的單調時鐘。
3. 依 §3 啟動主叫端、§4 啟動目標端，使用測試標籤 `TEST`；錄約 2 分鐘。
4. 確認主叫端有**新時間的 attempt／紀錄**，目標端狀態為 `Capture active`，`Samples` 一般有增加。測試一次短碼 `TEST` → `Mark event now`。
5. 依 §9 停止、匯出並複製測試檔。在電腦確認 caller session JSON、research 資料夾及 target JSON 都存在，事件有寫入。
6. 確認 research manifest 的 native capture 實際有檔，不只看「匯出成功」。這一步可先發現記錄／傳輸問題。

若主叫端明確未啟動、root／權限／儲存有錯，先修復。若系統運作正常但沒有 CNI，保留測試結果；場勘再確認這種條件是否有可觀察性。

## 2. 場域只需建立一次的對照表

### 2.1 六個核心固定點

以下代號是範例，要填成實際可辨識、可停留的位置；不用在現場貼任何標記。

| 代號 | 要選的位置 | 用途 |
|---|---|---|
| P1 | F1 某側內部，例如西側店面旁 | F1 水平位置一 |
| P2 | F1 另一側較內部 | F1 水平位置二；10 分鐘內部原地控制 |
| P3 | F2、盡量與 P1 水平對齊 | 與 P1 比較垂直差異 |
| P4 | F2、盡量與 P2 水平對齊 | 與 P2 比較垂直差異 |
| P5 | 出入口 G1 的門內、安全可停的位置 | 門內指紋；10 分鐘近門原地控制 |
| P6 | G1 門外、安全可停的位置 | 外部負例，包含可能自然失去 Wi-Fi 的情況 |

F1／F2 是本手冊代號，對照表必須寫實際樓層牌，例如「F1＝實際 2F、F2＝實際 3F」，不要假設所有場域都有相同命名。

另外記下：

1. `site_id`、建築名稱或私人代碼、日期、營業／人流概況。
2. G1 的**實體門線**：例如某一扇門的門框線；所有正式出入都跨同一條線。
3. 兩層簡圖、P1–P6、走廊、樓梯／電扶梯／電梯，以及可走的替代內部路徑。
4. 可取得的路徑長度／圖面尺度與來源。沒有可靠尺度時只報「哪一段走廊」，不捏造公尺精度。
5. 場域 Wi-Fi 連線方式，是否有 portal、重新登入或掉線。照常使用，不依看到的 cell 刻意選 AP。

**若要主張「辨識這棟建築」，正式資料需再有鄰近其他建築／另一側外部的負例。** 可事先指定 P7、P8，兩天各停 4 分鐘。若無法進入或無 CNI，仍記可用性限制；六點核心結果只代表受測內部與 G1 外部的區別，不能外推整棟專屬性或陌生建築能力。

### 2.2 主路線與已知點

場勘後選定一條**全程留在建築內**、可重複步行、最好跨 F1／F2 的主路線。預設：

`C0（F1 起點）→ C1（F1 上下樓設施前）→ C2（F2 出來後、可核對樓層處）→ C3（F2 終點）`

- C0／C3 可與 P1／P3 重合。C1／C2 選不擋人、能站定操作的位置。
- 固定上下樓方式，不在不同趟混用樓梯與電梯；步速只改變可正常步行的路段，不在樓梯奔跑、不在電扶梯改變站立習慣。
- 路線自然走完最好約 1–3 分鐘，讓移動中有多個 probe 機會；依場域實際情況選，不為等特定 ID 停住。
- 若跨樓路線不可行，可固定同樓 `C0→C1→C3`，但樓層追蹤只能使用另收的上下樓對照，不能假裝主路線已測過。
- 正式 Day 2 到各固定點時，事前指定至少一組不同的**內部抵達路徑**，記在表上；主路線本身仍保持相同，避免把「換抵達路」與「換主路線」混為一談。

## 3. 主叫端：每個採集日設定一次

在 CellIDTracker 的 **Probe** 頁面依序操作：

| 順序 | 實際操作 |
|---|---|
| 1 | `Victim number` 輸入研究目標電話，按 **Set victim number**，等成功訊息；只輸入而未按設定不算完成。 |
| 2 | **Comprehensive SIP research capture** 開啟；這是 SIP／環境記錄，不是錄音錄影。 |
| 3 | **Campaign ID** 兩機使用同一個，例如 `MALL_A_D1_YYYYMMDD`。每天明確更新，不依賴自動產生。 |
| 4 | Caller 的 **Condition label** 填 `D1_MAIN10`；Day 0／Day 2 分別改 `D0_PILOT10`／`D2_MAIN10`。 |
| 5 | `Run notes` 記場域與固定設定；**Moving (for paging test)** 保持 OFF，它不是自動移動標籤。 |
| 6 | **183 responses before rollover = 1**、**Auto restart probe = ON**、**Minimum interval between INVITEs = 10s**。 |
| 7 | 按 **Start session**，等顯示有效 Session ID／開始成功；接著另按 **Probe**，確認狀態 **Running**。前者不會自動開始發 probe。 |

主叫端在當日流程中連續記錄，不為每個點重開。保持位置／網路與設定固定；不用 Inter-carrier test，不清歷史。若因中斷需要重開，保留前檔並在清單記時間，新 session 也加入配對表。

**確認有新資料時看新時間／新 attempt，不只看畫面上的 CID。** 目前畫面可能在後續沒 CNI 時繼續顯示上一筆結果；這不表示新收到的 CNI 過時，也不表示每次都成功。地圖空白或線上定位失敗，不等於已取得的 cell 無效。

## 4. 目標端：每一段都用同一操作模板

### 4.1 本手冊如何減少逐筆標記

預設採「**一段一個 target session**」：固定點、單趟路線、單個 episode 各錄一檔。開始／結束本身提供時間邊界，固定點不另打事件。

- 所有段落使用當日相同 **Campaign ID**，但 target 的 **Condition label** 用段落代碼，例如 `D1_P1`、`D1_R01_P_N`、`D1_D01`。
- 這是刻意的 **一個 caller session 對多個 target session（1:N）**。Caller 與 target 的 condition 不必相同；用 campaign、target 標籤、起訖時間與配對表連結，session ID 不會相同。
- 目前不是一鍵自動配對；既有分析若只接受 1:1，之後需按這份索引處理，**不要求現場改檔名、合併 JSON 或手改原檔**。
- 核心正式日每天 26 個 target sessions：6 個固定點＋8 趟路線＋12 個 episodes；先前試錄另計。這省去許多起訖文字標記，但仍需開始／匯出操作，並非全自動。

按預設跨樓主路線完整做兩天，約 **110 個短碼事件**（路線 32、D 出入 32、S 出入 16、W 開關 16、N 錨點 14），另有 52 段錄製的開始／匯出與 condition 輸入；Day 0、異常或重做另計。這是省去逐筆 probe 標記後的實際負擔，並不是只需按幾次。先做 Day 0，確認值得繼續才負擔正式兩天。

### 4.2 每段的按鈕順序

1. 到該段已知的起點，站定；確認實際樓層／位置。
2. LocationData 停止狀態下填 **Campaign ID**、該段 **Condition label**；**Keep screen on** 開啟，本輪保持 App 可見。
3. 按 **Start**，確認 `Capture active`、Session 與錄製狀態；需要的精確位置、電話狀態與通知權限先授予。不要只憑有權限推定所有欄位必定有值。
4. 完成本段動作；只有 §7／§8 指定的少量 checkpoint／門線／切 Wi-Fi 需要手動事件。
5. 到該段已知終點，仍站在原處按 **Stop & export**；等 `Stopped... exported` 與 **Last export** 路徑。匯出完再離開。
6. 若顯示匯出失敗，App 可能恢復錄製：保留檔案，站在已知點重試並註記，不當作已停止。

固定點兩檔之間的走動沒有細真值；caller 原始資料保留，但不把這段直接標成前一點或下一點。路線／進出才使用連續 target 記錄。

### 4.3 現有手動事件的操作

錄製中才會出現 **Manual event marker**：

`Event label` 填短碼 → 到指定位置按 **Mark event now**。

按下的時間才是標記時間；每次按完文字會清空。可在安全站定處預填下一碼，之後到點按下，但沒有預設快捷鍵、回填或自動倒數。若操作必須停下，保留這個停頓；不要在樓梯／忙碌門線邊操作，不將晚補的標記當作精確過門時間。

## 5. Day 0：場勘，約 60–90 分鐘

1. 依 §3 開主叫端；目標端按 §4 分段錄。
2. **六點各 3 分鐘**：依 `P1→P3→P5→P4→P2→P6`。例如在 P1 設 `D0_P1`，按 Start，站定 3 分鐘，Stop & export；其餘照做。
3. 在 P2 再收 **10 分鐘原地控制**，標 `D0_STATIC`；全程不因 ID 變動而移動或換網路。
4. 做下列短行程；每趟獨立 session、起終點明確，必要時用 §7／§8 的短碼：
   - F1 同樓水平走動兩趟，方向相反。
   - F1→F2、F2→F1 各一趟；確認上下樓兩端位置。
   - G1 實際離開再回來兩個 episode；保留門線區間，門外至少停約 60 秒，這不是正式 120 秒評估。
   - 接近 G1、沒過門就返回兩個 episode。
5. 不要求現場等出某個 cell；自然沒有 CNI 的路段也完成動作與記錄。
6. 依 §9 收場。回電腦後先檢查：
   - 各點／樓層有哪些完整 ID、缺 CNI 比例、是否有數筆可用觀察。
   - 原地是否也會出現候選切換；上下樓變化是否只是同樓水平位置差異。
   - G1 兩側是否還可觀察。若走出即無 CNI，保留為端到端限制；另選 Wi-Fi 仍可用的內部邊界測辨識能力，不能把它稱為建築出口。
   - 手動事件、native capture、target 檔案是否完整。
7. 凍結正式六點、門線、主路線、checkpoint、到點路徑、手機設定與順序。若場勘未顯示可用差異，先縮小到粗區域、換場勘點或停止該方向；不用直接投入兩天完整採集。

Day 0 只用於選場與方法探索，不當獨立成功驗證。

## 6. 正式日：固定點／樓層＋原地控制（E1、E4）

### 6.1 每日順序與時間

| 日期 | 順序 |
|---|---|
| Day 1 | P1 → P3 → P5 → P4 → P2 → P6 |
| Day 2 | P6 → P2 → P4 → P5 → P3 → P1 |

每點的操作：

1. 抵達並核對點位／樓層；Day 2 使用預先指定的抵達路徑。
2. Condition 填 `D1_P1` 等，依 §4 開始。
3. P1、P3、P4、P6 各 **4 分鐘**；P2、P5 各 **10 分鐘**。從成功開始錄製起計時，不等特定 ID。
4. 全程同點正常持機；不刻意轉手機、切 Wi-Fi 或上下樓。若自然被打斷，記異常與實際時間，不刪掉該版。
5. 還在該點時 Stop & export，確認成功後前往下一點。

**取資料規則先固定：** 各點前 4 分鐘用於 E1；P2／P5 整段 10 分鐘用於 E4。不能事後挑最漂亮的 4 分鐘；E1／E4 重疊時間去重。每日唯一固定點時間 **36 分鐘**，兩天共 **72 分鐘**。

這組同時檢查：同樓不同水平位置、近似相同水平位置的不同樓層、門內／門外、原地切換。若加入 P7／P8，照同樣 4 分鐘流程，並在 Day 0 後就固定順序與定義。

## 7. 正式日：主路線／切換地標（E2）

### 7.1 共 16 趟，每天八趟

`P`＝C0→C1→C2→C3；`M`＝反向。`N`＝平常正常走速，`B`＝較快但仍正常的走速；不跑步。

| 趟次 | Day 1 condition 後綴 | Day 2 condition 後綴 |
|---|---|---|
| R01 | P_N | P_B |
| R02 | M_B | M_N |
| R03 | P_B | P_N |
| R04 | M_N | M_B |
| R05 | P_B | P_N |
| R06 | M_N | M_B |
| R07 | P_N | P_B |
| R08 | M_B | M_N |

每天每個「方向×步速」兩趟。完整例：`D1_R01_P_N`。

### 7.2 每趟詳細操作

1. 到 C0（反向則 C3），填當趟 condition，Start。站定約 **30 秒**；開始時間即提供已知起點，不另打 C0 起點事件。
2. 錄製中預填第一個 checkpoint 短碼，按指定方向與步速走。
3. 正向到 C1，安全站定，按 `C1`；在此填好下一碼 `C2`。完成操作後才開始上下樓。反向先到 C2 就按 `C2`，再預填 `C1`。
4. 到另一層已知落點、確認樓層後，站定按另一個碼。每趟只需 **C1、C2 兩個中間事件**；操作停頓保持相同習慣，實際停多久保留在資料中。
5. 走到 C3（反向則 C0），站定約 **30 秒**後 Stop & export。結束時間提供已知終點，不另打終點碼。
6. 核對當趟完成／中斷、步速、意外停下、用錯動線等；所有版都保留。下一趟重新錄製。

16 趟合計 **32 個中間事件**。同樓替代主路線若只有一個中間點，則每趟一個；分析能界定的空間範圍也比較粗。

**真值如何使用：** 正向 C0→C1 為 F1、C1→C2 為換樓未知區間、C2→C3 為 F2；反向 C3→C2 為 F2、C2→C1 為換樓未知區間、C1→C0 為 F1。這以指定路線確實留在該樓層為前提，不硬分上下樓瞬間。

起終點約 30 秒是停留，不當步行；但本流程沒有另按起步／抵達事件，不能精確用 session start＋30 秒或 end−30 秒回推出移動邊界。C0／C3 先作位置錨點，需要精確動靜分段時另標或保留不確定緩衝。兩 checkpoint 間只知道所處路段，不用均速插值製造公尺位置。

收到 A、下一筆 B 的「觀察切換」可能跨過沒採到的 cell。比較 B、A→B、短序列能否縮小候選路段，並與原地／替代路徑對照，不能直接稱為精確 handover 點。本輪有操作停頓的路線成果，只適用這種走法；自然不停步的表現需成功後另測。

## 8. 正式日：離開與非離開對照（E3）

### 8.1 每天十二段

| 類型 | 每日數量 | 實際要做的事 |
|---|---:|---|
| D01–D04 | 4 | 真正離開 G1，外部持續至少 150 秒，再回來 |
| N01 | 1 | 接近 G1、不跨門，返回 |
| N02 | 1 | 替代內部走廊路線，全程不出建築 |
| N03 | 1 | F1→F2→F1，始終在建築內 |
| N04 | 1 | 內部走廊停約 30 秒、折返 |
| W01、W02 | 2 | P2／P5 原地關再開目標 Wi-Fi |
| S01、S02 | 2 | 真正短暫離開約 20／60 秒後返回 |

| 日期 | 執行順序 |
|---|---|
| Day 1 | N01, D01, W01, S01, D02, N02, N03, D03, S02, W02, D04, N04 |
| Day 2 | D01, N01, S01, W01, N02, D02, D03, N03, W02, S02, N04, D04 |

各段 condition 例如 `D1_D01`、`D2_W02`。這些代碼只表示真實做的實驗，不輸入 caller 模型。

### 8.2 不必在門線邊按手機：用四個短碼夾住出入

在 G1 兩側選固定、安全、相距盡量短的標記位置，事先畫在圖上。

| 短碼 | 何時按 |
|---|---|
| X0 | 準備離開，還在門內位置 |
| X1 | 跨門後，已到門外位置 |
| I0 | 準備返回，還在門外位置 |
| I1 | 跨回後，已到門內位置 |

X0 按完後，可在門內站定時先填好 X1 再走；I0 後同理預填 I1。**實際 EXIT 在 [X0,X1]，ENTER 在 [I0,I1]**，不需要錄影，也不假裝按鈕等於過門瞬間。現場清單記哪些標記延遲、打錯、漏按。

### 8.3 D：持續離開，每天四次

1. 目標到 P5／指定門內基準點，condition `D1_D01`，Start；門內站定 **120 秒**。
2. 按 X0，預填 X1，正常走出 G1，在已知門外位置按 X1。
3. **從 X1 開始再計至少 150 秒**，整段留在外部。因 X1 已確定人在外，保證完整覆蓋實際離開後的 120 秒評估窗；不要只從開始走動計時。
4. 即使外面無 Wi-Fi／無 CNI，target 不停止，caller 不更改設定，也不接熱點。
5. 門外按 I0，預填 I1，跨回後在門內按 I1。
6. 回原門內基準點站定 **120 秒**，Stop & export。下一段重新開始；此預設分段流程不把前段恢復時間重複宣稱為下一段的已錄基準。

四次盡量走相同門線，外部落點保持可重複；不要依當時 ID 決定何時出去或回來。

### 8.4 N：四種「沒有離開」

每段在指定內部起點 Start，先站 **60 秒**，完成下列動作，回內部終點再站 **60 秒**，Stop & export。**全程沒有 EXIT**，不打 X/I 假事件。

- **N01**：向 G1 靠近，到預先指定的門內折返點，直接返回；可按 `TURN` 留折返點。
- **N02**：走與主路線不同的內部走廊，回到已知內部點；不必逐轉角標，這段主要評「不應報離開」。
- **N03**：F1 上 F2 再回 F1。四個必要樓層錨點：`U0`（F1 上樓前）、`U1`（到 F2）、`V0`（F2 下樓前）、`V1`（回到 F1）；中間為換樓區間。
- **N04**：走到指定內部走廊點，按 `PAUSE`，停約 30 秒，按 `BACK` 後折返回終點。

N02／N04 同時提供地標的替代路徑、停下／折返對照，不另算新增主路線重複。

### 8.5 W：原地斷 Wi-Fi，每天兩次

W01 在 P2、W02 在 P5；整段身體停在同一已知位置，只切目標手機 Wi-Fi。

1. condition `D1_W01` 等，Start，Wi-Fi 正常開啟狀態站 **60 秒**。
2. App 按 `OFF0`，再去系統設定關 Wi-Fi，回 App 按 `OFF1`。真實關閉動作在兩標記之間；不要把之後 cellular 接手時間當開關瞬間。
3. 從 OFF1 開始保持關閉約 **90 秒**，人不移動；不用飛航模式或關行動網路替代。
4. 按 `ON0`，去系統開 Wi-Fi，回 App 按 `ON1`。
5. 原地等 **120 秒**，Stop & export；記 Wi-Fi／Wi-Fi Calling 是否自然恢復，沒有恢復也保留。

這段需要暫時離開 App 操作系統介面；回來檢查錄製仍在，若有缺口就標註。OFF／ON 四碼是為保留切換不確定區間，並非自動偵測的結果。

### 8.6 S：短暫離開再回來，每天兩次

1. 依 D 的方式 Start，門內基準 **120 秒**，X0→跨門→X1。
2. S01 在門外約停 **20 秒**，S02 約 **60 秒**，然後 I0→跨回→I1。
3. 門內站 **120 秒**，Stop & export。
4. 真實外部時間依出入標記區間計算；20／60 秒是操作目標，不是捏定的真值。若走路／輸入讓外部時間更長，如實保留。

短暫事件獨立計分，不納入 D 的「在外維持完整 120 秒」指標；不能因最後已回來就說從未離開。

### 8.7 恢復與異常的共同規則

- 不等到某個喜歡的 cell 才開始下一段；按固定基準／恢復時間進行。
- 明確未連回 Wi-Fi、portal 未登入、App 停止時，修復並記時間；保留失敗版。若需延長或重做，使用新段落代碼，例如 `D1_D02_R2`，原 D02 仍在。
- 系統正常但沒有 CNI 的 episode 仍是研究結果，不能刪除後只留成功版。
- 固定點移動時附帶跨門的資料仍保留；沒有完整事件真值時單列「附帶／粗時間」，不暗中加進八次正式持續離開。

## 9. 每日結束：停止、匯出、備份

### 9.1 現場收場順序

1. 目標完成最後一段，按 Stop & export，確認 Last export；檢查當日各段完成與異常清單。
2. 回主叫端按 **Stop**，等狀態確實 **Idle**，再按 **Stop & export**。直接按匯出不會替你停止 probe。
3. 等顯示 caller session JSON 與 research 匯出路徑，確認 active session 結束。Caller 比 target 多出的收場尾段沒有細真值，保留但不納入有標籤評分。
4. 若主叫端仍未 Idle，不強制清 App；等待或處理明確錯誤，保留中斷紀錄。

### 9.2 必須帶回的檔案

主叫端通常在：

```text
/sdcard/Android/data/com.example.cellidtracker/files/experiment_sessions/
  <callerSessionId>.json
  <callerSessionId>_research/
    manifest.json
    session_metadata.sanitized.json
    caller_context.sanitized.jsonl（含輪替檔）
    diagnostic.sanitized.log
    native/sip_capture.sanitized.jsonl（含輪替檔）
```

目標端通常在：

```text
/sdcard/Android/data/com.example.locationdata/files/ground_truth_sessions/
  <targetSessionId>.json（每段一檔）
```

以實際畫面路徑為準。用現有 USB／電腦傳輸方式複製，caller 與 target 分開資料夾，保留原始檔名。Android/data 在部分手機的檔案管理器受限制；可沿用既有已連通的開發工具傳輸，不需另裝新 App。

- **History → Export all 不能取代 session JSON＋research 資料夾。** 現有 App 也不會自動產生 ZIP。
- `pull-research-session.sh` 不是已驗證可同時拉兩 App 的一鍵工具；target 匯出要另外複製。
- 不必例行複製 App 私有金鑰／原始 capture 目錄。普通 caller session JSON 並未匿名化，整包資料作私人研究保存。
- Capture 有輪替上限；場勘後與每日匯出都查 native 時段、數量、遺失／錯誤統計。若長時間不夠保留，下一次改在固定區塊邊界分 caller sessions，全部列入索引，不事後假裝早期 capture 完整。

### 9.3 一張配對／完成清單

每個 target session 一列，可用試算表或文字，不必改 App：

```text
campaign | caller session(s) | target session | condition | 實際起點→終點 | 完成/偏離 | 備註
MALL_A_D1_YYYYMMDD | <caller id> | <target id> | D1_P1      | P1→P1 | 完成 | 4 分鐘
MALL_A_D1_YYYYMMDD | <caller id> | <target id> | D1_R01_P_N| C0→C3 | 完成 | C1/C2 皆有標
MALL_A_D1_YYYYMMDD | <caller id> | <target id> | D1_D01    | P5→外→P5 | 完成 | X0/X1/I0/I1
```

另保存點位對照表、路線圖、實際樓層名、設備／設定、對時結果、意外來電／手動中斷、自然與刻意斷 Wi-Fi 的差異。未完成段落照樣列出，避免隔天誤以為資料遺失或成功完成。

## 10. 回電腦後的檢查與分析順序

這部分是分析工作，不要求你在百貨公司現場逐筆處理。

### 10.1 先驗資料完整性

1. 對清單：Day 1／Day 2 各 6 固定點、8 路線、12 episodes；附加點、試錄、失敗重做另外列。
2. 以共同 campaign、時間與索引作 1:N 配對；偵測重疊、漏檔、跨越重啟的段落。無 target 記錄的 caller 轉場不自動補標。
3. 查 target 起訖、事件短碼與位置定義；不把室內 GPS／高度當樓層標籤。確認實際採樣間隔、fix age、radio age、registered 狀態與缺值。
4. 查 caller 每次 attempt、實際發送時間、成功／無 CNI／timeout／重啟。完整 cell tuple 分類，不只看 CID 數字或前綴。
5. 從 native capture 找真正帶該 CNI 的回應到達時間；不能一律拿第一個 provisional 時間替代。沒有完整 capture 時降低時間主張，不猜精確延遲。
6. 查 manifest native 檔數、copy errors、輪替／遺失等；「匯出成功但 0 個 native 檔」仍是證據不足。
7. Target sample 中斷與 caller 無 CNI 分開：室內 fused 更新停住可能連帶停止 target radio samples；已知點位／手動事件仍有獨立真值，但缺少的診斷資料不能補造。

### 10.2 四個方向逐一比較

| 方向 | 要比較的最小方法 | 必報結果 |
|---|---|---|
| 建築物／區域 | 多數類別、目前單筆 ID、30／60／120 秒集合／比例、序列 | 混淆、外誤內、未知比例、等待時間；場域範圍／外部負例限制 |
| 樓層 | 單筆 vs 歷史；同樓不同水平點 vs 同水平跨樓；冷啟動 vs 已知起點追蹤 | 精確樓層／預定樓層群、換樓延遲、未知；是否只靠已知起點／走法 |
| 切換地標 | 目前 B vs 觀察 A→B vs 短序列 | 相同真值保留率下候選路段是否變短；按方向／步速比較，原地與替代路徑誤觸發 |
| 離開 | 有證據才確認離開，缺資料為未知；與原地 W、近門 N 對照 | D 的 30／60／120 秒內偵測、誤報／內部小時、短暫事件漏報、未知時間、全部 attempt 成本 |

樓層另做「只有動線圖＋時間／已知起點」基準，確認 ID 是否額外提供資訊。冷啟動不可使用抵達前的路線／起點標籤；有歷史追蹤則需說明如何取得初始區域，不能偷給正確樓層後混在一起報。

高度的附帶分析：用固定點與上下樓已知區間，檢查現有 fused altitude 同層漂移、跨層重疊、回原層一致性。若未驗證，不能用其自動補全樓層。**本輪不要求氣壓計，也不要求新增感測程式。**

### 10.3 凍結測試與時間評分

1. Day 0／Day 1 開發方法，按完整 trip／episode 調整；Day 2 作凍結測試，不隨機拆相鄰樣本。若 Day 2 後改方法，需新日期驗證。
2. 只使用決策當下已收到的資訊，不能看完整路線未來的 ID 再宣稱當時已定位。
3. 每個離開警報最多配對一個 EXIT，必須在離開後、返回前；重複警報不增加成功數。提早預測另列，不能當確認離開。
4. EXIT∈[L,U]、警報時間 A，延遲為區間 [A−U,A−L]，再納入兩機鐘差不確定度；A 在過門區間內時不能確定是否已離開。無法確認的截止秒數結果標模糊／未知，不挑有利端點。
5. 返回也有 ENTER∈[I0,I1]：警報在 I0–I1 之間時，是否已返回不確定；不能一律拿 I1 當真實返回而計成功。忽略鐘差時，A≥X1 且 A<I0 才能確定落在此次外部區間；其他邊界情況保留模糊，加入鐘差後再縮小可確定範圍。
6. 未偵測、失聯、缺 CNI 的真實離開都留在分母。固定點／E4 重疊時間去重；八次持續離開不被數百 attempts 擴充成數百獨立事件。

## 11. 最後才做「減少 probe」實驗

### 11.1 先用已收的 10 秒資料重播

1. 在 Day 0／Day 1 選定共用離開辨識器與規則，凍結。
2. 比較固定 10／30／60 秒與有最大間隔的候選動態策略，例如穩定時延長、接近出口證據出現時縮短。
3. 策略只能看到自己此前選到、且當時已收到結果的 attempts；不能看被跳過的 ID，也不能在發送時先知道稍後結果。
4. 在原有 attempts 中選「第一筆不早於策略預定下次查詢時間」的紀錄；同時不得早於當下決策時刻、上一筆實際發送＋本輪 10 秒間隔與原流程允許的時間。每次按選到的實際時間繼續排程，不追趕理想時鐘，不看該筆是否成功才挑。實際時間與流程限制照留。這是重播近似，不是已實測的精確 30／60 秒網路行為。
5. 在相同或相近漏報、誤報、延遲、未知比例下，比每小時全部嘗試數；不只跟最密集 10 秒比，要與合格的固定慢速組比。

### 11.2 有收益才另日實測

1. 現有 App 可選固定 30／60 秒：**每換設定先 Stop→Idle→Stop & export，再換 interval／condition 並開新 session**，避免 metadata 與實際設定不同。
2. 動態排程目前未實作。若重播有收益，先另行實作並驗證執行／決策記錄，再排前瞻採集；本輪不用假想的「adaptive」按鈕。
3. 初始前瞻比較可用四個條件：固定 10、30、60 秒、凍結動態策略；在兩個新日期各做一輪，條件順序 Day A 為 10→30→60→動態，Day B 反向。這只是再次初篩；需要更多平衡日期才可做可靠效能主張。
4. 每個條件各做：原地 10 分鐘、D 持續離開 2 次、N 近門不出／內部走動各 1 次、W 原地 off/on 1 次、S 短暫離開 1 次。沿用 §8 真值方式，使用同類路線，保留全部失敗。
5. 若四條件同日過長，分成兩個條件／日期，隔次交換先後並重複；日期差異需明列，不能把不同日當完全相同環境。所有策略每次使用相同的初始化／未知狀態規則，不先免費給某組額外密集歷史。
6. 重播收益若未在實測重現，就不宣稱已省 probe；即使成功，停留時仍需定期檢查，最大設定間隔不等於失聯時的延遲保證。

## 12. 何時繼續、縮小或停止

| 發現 | 下一步 |
|---|---|
| 同點跨日／換抵達路徑仍有可重現 ID 差異 | 繼續區域／樓層；增加未採點與第三日期，之後才擴到第二建築、其他手機／業者 |
| 只能分低樓／高樓，不能分單層 | 用訓練資料事先定義粗區域，在新日期驗證；保留精確樓層失敗結果 |
| A→B 比 B 能在同等真值保留率下縮小路段，原地不常誤觸發 | 值得擴充地標；再測不停步自然走法、其他到達路線與更多日期 |
